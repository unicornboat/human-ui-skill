# Human UI

目标不是禁止紫色、渐变或卡片，而是让每个视觉决定服务于内容、品牌或操作。尊重用户提供的参考、设计系统和技术约束；不要把个人审美当作硬规则。

## 工作方法

1. 明确页面任务、目标用户、最重要的操作，以及用户要求“相似”还是“精确复刻”。先读现有组件和样式，保留有效模式。
2. 建立信息层级。区分主标题、关键数据、主要操作、辅助说明。删减重复容器和空泛文案；用真实数据或明确标记的示例代替营销套话。
3. 对每个渐变、阴影、圆角卡片、装饰图形和图标问：去掉它，理解或操作是否变差？没有明确作用时删除或弱化。不要将“去 AI 味”机械理解为全部改成黑白极简。
4. 形成少量一致的设计决策：颜色用途、字体层级、间距节奏、边界和状态。让页面具备与产品内容有关的特征，而不是套用通用 SaaS 首屏。
5. 实现完整状态：默认、悬停/焦点、加载、空状态、错误和移动端；仅覆盖任务涉及的状态。检查可读性、对比度、键盘操作与响应式布局。
6. 用运行中的实际页面截图检查外观，同时运行适用的自动测试。不要仅凭代码判断视觉效果。

## JEV 判定（条件使用）

若 TypeSafe AI 的 JEV 可用且 `TYPESAFE_API_KEY` 存在，完成 UI 实现后必须使用。否则跳过，记录未使用原因，不伪造结果，也不要让 JEV 成为交付阻碍。调用前核对 [官方文档](https://docs.typesafe.ai/) 的当前 API、请求格式和模型；密钥只从环境变量读取，绝不打印或写入仓库。

给 JEV 提供任务要求、实际实现、可用参考和实际截图。按任务拆成具体、可判定的问题，例如：主操作是否最突出；卡片是否只承载有分组价值的内容；移动端是否保持层级；若有参考，视觉关系是否达到用户要求的相似度。使用当前文档支持的类型化问题（如 `score`、`noul`）；不要把多个独立维度塞进一个总分。要求各选项的百分比，并将低分关键项与截图、代码和测试结果核对后修正。JEV 分数不是测试通过率，也不能替代人工验收。

最终简要报告设计取舍、实际验证、JEV 判定问题与选项百分比（若使用），以及尚存差异。不要声称“完全没有 AI 味”；说明可观察的改进。
